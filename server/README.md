# 듀얼 서버

실시간 대전용 WebSocket 서버. 클라이언트와 **같은 시뮬레이션 코드**를 import한다
(`../src/game/sim.js`, `config.js`). 규칙이 갈라지면 즉시 데싱크가 나므로 절대 복사해두지 말 것.

## 로컬 실행

```bash
cd server
npm install
npm start           # ws://localhost:8080
```

클라이언트는 기본으로 `ws://localhost:8080`에 붙는다. 바꾸려면 프로젝트 루트에 `.env`:

```
VITE_SERVER_URL=wss://내서버.onrender.com
```

## Render 배포

1. Render에서 **New → Web Service**, 저장소 연결
2. **Root Directory**: `server`
3. **Build Command**: `npm install`
4. **Start Command**: `npm start`
5. 인스턴스 타입 Free

Render가 `PORT` 환경변수를 주므로 서버가 그 포트로 뜬다. 주소는 `https://...onrender.com`이고,
클라이언트에서는 `wss://...onrender.com`로 접속한다 (http→ws가 아니라 **https→wss**).

무료 플랜은 15분간 접속이 없으면 잠들고 깨는 데 1분쯤 걸린다.

## 장애 알림 (디스코드)

웹후크 주소는 **Render 환경변수 `DUEL_ALERT_URL`** 로만 넣는다 (파일·코드·로그 어디에도 안 남긴다).
값이 없으면 아무것도 안 보내고, 서버가 꺼지는 방식도 예전과 똑같다.

| 머리말 | 뜻 | 무엇 |
|---|---|---|
| [긴급] 빨강 | 사람들이 지금 못 하거나 무언가를 잃는다 | 서버가 오류로 꺼짐, 점수를 못 적음(판 전 점수를 못 읽은 판 포함), 광고 보상을 못 줌, 로그인 확인 실패(Firebase), 저장소 키가 깨짐, 계정 삭제 실패, 메모리 90%, 서버가 1초 넘게 멈춤, 처리 못 한 오류 |
| [주의] 주황 | 일부 기능이 안 되거나 곧 문제 | Firestore 읽기·쓰기 실패(친구·퀘스트·티켓·순위표·보상·코인 구매 등), 메모리 80%, 서버가 30초 넘게 느림 |
| [정상] 초록 | 돌아왔다 | 메모리 정상, 서버 속도 정상 |
| [알림] 파랑 | 소식 | 서버 켜짐, 서버 꺼지는 중(배포·재시작) |

- 같은 문제는 처음 한 번만 자세히, 그 뒤 5분 동안 생긴 것은 "같은 문제 N번 더" 한 통으로 묶는다
- 알림마다 밑줄에 메모리·방 수·게임 중인 사람 수·한국 시각이 붙는다
- 점수·광고 보상·계정 삭제처럼 손으로 고쳐야 할 수 있는 일에는 **계정 uid** 를 적는다
- 안 보내는 것: 웹후크 주소, 로그인 증표, 서비스 계정 키(`FIREBASE_KEY`) 내용, 접속 IP
- "서버 켜짐" 바로 앞에 "꺼지는 중" 이 없었다면 갑자기 꺼졌다가 다시 켜진 것이다 (메모리 초과 등)
- `/health` 의 `alert.on` 이 `true` 면 켜진 것, `alert.fail` 이 늘면 주소가 틀린 것

**서버가 아예 죽으면 서버가 알림을 못 보낸다.** 그건 Render 의 메일 알림으로 받는다 —
서버 Settings → Health Checks 에 `/health`, Notifications 에서 실패 알림을 켠다.
[stated] **업타임 봇(UptimeRobot)은 안 쓴다** (2026-10-20 — 앱을 켜는 즉시 서버를 깨우므로).
그래서 무료 플랜은 15분 무입력이면 잠들고, **잠들 때 "꺼지는 중", 깰 때 "서버 켜짐" 알림이 온다** (그대로 두기로 함).
`/alarm`(문제 없으면 200 `ok`, 메모리 90% 이상·저장소 키 깨짐이면 503)은 나중에 바깥 감시를 붙일 때 쓴다.

조절(보통은 안 건드림): `DUEL_ALERT_GROUP_MS`(묶는 시간, 기본 5분), `DUEL_MEM_MB`(메모리 한도, 기본은 컨테이너 값 또는 512).

    node test/alert.test.js     # 가짜 디스코드로 진짜 서버를 띄워 알림을 확인

## 구조

- 접속하면 빈 자리가 있는 방에 넣고, 없으면 새 방을 만든다
- 방에 들어오면 `hello`(슬롯 번호) + 현재 상태 스냅샷을 보낸다.
  **방은 이미 돌고 있으므로 스냅샷 없이는 클라가 시작점을 못 잡는다**
- 두 자리가 차면 `go`를 브로드캐스트
- 들어오는 메시지의 `pid`는 **소켓의 슬롯으로 덮어쓴다**. 클라가 보낸 pid를 믿으면
  남의 캐릭터를 조작할 수 있다
- 모든 방을 타이머 하나로 굴린다. 방마다 `setInterval`을 두면 방이 늘수록 틱이 흔들린다
- 15초마다 ping/pong으로 죽은 소켓을 정리한다 (모바일은 연결이 조용히 끊기는 경우가 많다)

## 현금 결제 (구글 플레이)

앱이 결제 창에서 받은 구매 증표를 `POST /pay` 로 보내면, 서버가 **구글에 직접 확인**한 뒤 지급하고
구글에 소모(마무리)까지 한다 (`pay.js`). 6시간마다 환불 목록을 보고 환불된 것은 회수한다.

- 열쇠: Render 환경변수 `FIREBASE_KEY` 의 서비스 계정을 그대로 쓴다 (따로 넣으려면 `DUEL_PLAY_KEY`)
- 구글 클라우드(같은 프로젝트)에서 **Google Play Android Developer API** 를 켠다
- 플레이 콘솔 > 사용자 및 권한 > 그 서비스 계정 이메일 초대 > 이 앱에
  **재무 데이터 보기** · **주문 및 구독 관리** 권한. 퍼지는 데 최대 하루 걸릴 수 있다
- 상품 ID 는 `src/game/skins.js` 의 `sku` 와 같아야 한다 (27개)
- 마무리를 못 하면(3일 지나면 구글이 자동 환불) [긴급] 디스코드 알림. 앱은 켤 때마다 마무리 안 된 구매를 다시 보낸다

    node test/pay.test.js        # 가짜 구글로 진짜 서버를 띄워 확인·지급·소모·환불 회수를 본다
